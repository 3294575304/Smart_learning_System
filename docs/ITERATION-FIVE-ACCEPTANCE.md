## 1. 验收结论

当前仓库已经贯通以下确定性链路：

> 正式课程知识图谱 → 教师审核题目主/次知识点绑定 → 作业首次发布冻结绑定快照 → 自动/人工批改生成追加式答题证据 → 生成版本化课程知识掌握度 → 师生按归属查询结果与证据

该链路满足版本可追溯、历史不可变、输入幂等、教师/学生权限隔离和旧作业不自动回填的约束，可作为后续 Python 判题、画像快照和课程图谱推荐的基础。

《项目计划书》2.4 版同时要求 Python 编程题、隔离沙箱判题、统一学习事件、画像快照、置信度/证据不足规则、掌握度与证据界面以及 AI 批量匹配。本记录验收时上述能力尚未落地；之后统一学习事件和真实隔离执行器门禁已在迭代五 A 完成，但 Python 题型、正式判题和画像仍未完成，因此本记录不能作为“迭代五整体完成”或“V1.0 完成”的依据。

## 2. 当前已实现功能

### 2.1 题目与课程知识图谱绑定

- 教师可在自己有权访问的课程中，为自己创建的题目绑定一个主要知识点和多个不重复的次要知识点。
- 绑定使用课程内稳定身份 `KnowledgeGraphConcept`，同时保存来源正式图谱版本和具体 `PublishedKnowledgeGraphNode`，避免把稳定 Concept 与版本节点混用。
- 服务端同时校验教师、题目、课程、正式图谱版本、节点和 Concept 归属；跨教师、跨课程资源使用 404 防枚举语义。
- 绑定集合保存 revision，并使用乐观并发避免两个编辑会话静默覆盖。
- 教师界面支持知识点搜索、主/次绑定、来源版本过期提示、保存冲突提示和清空确认。

### 2.2 作业发布快照

- 作业首次发布时，将当时的题目绑定修订、主/次类型、来源图谱版本和节点冻结到 `AssignmentQuestionConceptSnapshot`。
- 快照记录发布时能否解析到课程正式图谱，并保存解析到的正式版本和节点。
- 重复发布不会重复生成快照；题目后续改绑或课程后续发布新图谱均不会改写历史作业快照。
- 该能力上线前已发布的旧作业不自动回填，避免制造无法审核的历史关联。

### 2.3 答题知识证据

- 只有已发布作业快照成功解析到正式图谱、且已经完成有效评分的答案，才会生成 `StudentAnswerConceptEvidence`。
- 客观题自动批改和简答题人工批改均可形成证据，并保留学生、课程、作业、提交、答案、题目、快照和 Concept 引用。
- 重新批改生成新 revision，并使用 `supersedesEvidenceId` 保留修订链；撤销有效评分生成新的撤销证据，不覆盖旧记录。
- 相同评分输入使用 SHA-256 指纹幂等复用；并发重复评分不会重复累计掌握证据。
- 未绑定题目、未解析绑定、未评分答案和无效满分不会进入有效掌握度计算。

### 2.4 版本化课程知识掌握度

- 按课程和学生保存 `StudentCourseConceptMasteryState`，每次输入变化追加 `StudentCourseConceptMasteryRevision`，不覆盖历史修订。
- 计算使用实际得分/可得分聚合，保留证据数、去重答案数、首次/最近证据时间和确定性等级。
- 修订保存规则版本、输入指纹和生成时间；相同证据输入幂等复用已有修订。
- 查询结果区分当前图谱可解析、当前版本缺失和没有当前正式图谱，并保留历史来源图谱分组与最近证据引用。
- 学生只能查询自己已加入课程的掌握度；教师只能查询自己课程中有效成员的掌握度。

### 2.5 与现有能力的边界

- 现有 MVP 推荐仍消费全局 `KnowledgePoint` / `StudentKnowledgeMastery`，尚未消费本迭代的课程 `KnowledgeGraphConcept` 掌握度。
- 当前掌握度只来自既有客观题自动评分和简答题人工评分；这些新评分现已先写统一学习事件再投影证据，但尚无 Python 判题结果。
- 当前提供师生查询 API，但没有教师/学生掌握度与证据可视化页面，也没有正式画像快照。

## 6. 下一步开发建议

下一步继续遵循计划书的 A/B/C 顺序，先解决安全和数据契约，再做界面及 AI 增强。

### P0：迭代五 A——任务、学习事件与沙箱契约

1. 定义最小统一学习事件：事件类型、版本、学生/课程、发生时间、来源类型与来源 ID、Concept 引用、分值、幂等键、撤销/替代引用和规则版本。
2. 定义判题任务状态机：`PENDING → RUNNING → SUCCEEDED/FAILED/CANCELLED`，保存进度、尝试次数、可重试错误、开始/结束时间、输入指纹和唯一幂等键。
3. 先选择并验证真正隔离的执行后端。应用服务只提交任务和读取脱敏结果，不在 Next.js 进程或普通本机子进程中执行学生代码。
4. 自动化验证禁网、只读/临时文件系统、进程数量、CPU、内存、超时和输出上限；任一安全门禁不能证明时，不开放学生代码执行。

退出门禁：相同任务重试不重复生成运行、事件、证据或成绩；资源限制和隐藏用例不泄露均有自动化测试。

### P0：迭代五 B——Python 基础判题纵切

1. 增加 Python 编程题型、标准代码、公开样例、隐藏测试用例和分值规则，并在作业发布时冻结完整判题配置版本。
2. 学生运行公开样例与正式提交分离；正式提交只返回用例序号、状态、得分和安全错误摘要，不返回隐藏输入、期望输出、沙箱路径或内部异常。
3. 保存源代码、标准化运行结果、耗时、内存、错误类型和执行器版本；按测试用例结果确定性计算基础分。
4. 判题成功后写统一学习事件，再由现有 Concept 快照生成追加式知识证据；判题服务失败不能阻塞普通题目提交和已发布成绩查询。

退出门禁：同代码、同用例、同执行器版本结果一致；语法错误、运行错误、超时和内存超限可区分；隐藏用例、网络和宿主文件不可访问。

### P0：迭代五 C——画像快照、证据界面与批量映射

1. 让既有作答和 Python 判题统一写入或投影为同一学习事件契约，保留原始事件并支持按规则版本重算。
2. 在当前课程掌握度修订之上增加画像快照，明确证据数量、置信度、更新时间和“证据不足”规则；出勤、活跃度、自述和客观掌握证据分开保存。
3. 增加学生和教师页面：课程/学生选择、掌握度摘要、文字结论、更新时间、当前图谱解析状态、证据下钻、空状态、错误和重试路径。
4. 最后接入 AI 批量候选匹配。AI 只生成带置信度的候选，教师批量确认后才写正式绑定；AI 失败时人工绑定继续可用。

退出门禁：同事件输入和同规则生成同一快照；结论可下钻到原始证据；未登录、角色不符、跨教师、跨课程和非本人访问测试通过。

### P1：迭代六联动准备

完成迭代五 C 后，再让现有推荐流程消费正式课程图谱、画像快照和已审核课程题库。不要同时维护两套互相漂移的课程掌握度；迁移旧 MVP 推荐链路前应先定义兼容读取、灰度切换和历史推荐解释方案。

## 7. 建议演示路径

1. 教师打开自有题目，在已发布课程图谱中搜索并绑定一个主要、一个次要知识点。
2. 用两个页面同时编辑同一绑定，验证过期 revision 不会覆盖最新保存。
3. 发布包含该题目的作业，记录绑定修订和正式图谱版本。
4. 修改题目绑定并发布新图谱，验证历史作业快照保持不变。
5. 学生提交客观题，教师对简答题人工评分并重新批改，查看追加式证据和掌握度修订变化。
6. 撤销一个有效评分，验证旧证据保留、新撤销修订生效且掌握度可重算。
7. 分别使用学生本人、无课程成员、其他教师和未登录请求验证权限边界。
8. 明确展示当前没有 Python 运行入口、画像快照和掌握度页面，避免把后端基础链路演示成完整迭代五。
