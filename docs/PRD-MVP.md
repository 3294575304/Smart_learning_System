## 0. 文档约定与产品边界

### 0.1 名词定义

| 名词         | 定义                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| 私有题目     | 由教师创建，仅创建者可管理和使用的题目。                                 |
| 公共题目     | 由管理员维护、所有教师可查看并选入作业的题目；教师不能直接修改公共题目。 |
| 客观题       | 单选、多选、判断、填空题，可按确定性规则自动批改。                       |
| 主观题       | 简答题，MVP 由教师人工评分；AI 只提供辅助建议，不直接决定最终成绩。      |
| 提交         | 学生确认交卷后形成的一次不可变答题记录。MVP 每份作业仅允许成功提交一次。 |
| 知识点掌握度 | 学生在某知识点下已批改题目的得分率，按题目分值加权计算。                 |
| AI 降级      | AI 不可用、超时或输出校验失败时，系统使用规则统计结果继续提供核心功能。  |

### 0.2 核心约束

1. 所有功能必须在登录后使用，登录页和身份校验除外。
2. 平台采用 `ADMIN`、`TEACHER`、`STUDENT` 三角色 RBAC；一个 MVP 账号仅拥有一个角色。
3. 教师只能访问自己创建的班级、私有题目、作业及对应学生数据。
4. 学生只能访问自己已加入班级中的作业，以及自己的提交、成绩、错题和学情数据。
5. 管理员可以治理平台资源，但不能冒充教师提交成绩，也不能替学生答题。
6. 分数、正确率、提交状态、资源归属和推荐候选过滤均由普通程序计算，不交给 AI。
7. AI 输出必须为 JSON，经 Zod 校验；首次失败后重试一次，再失败则执行规则降级。
8. AI 失败不得阻止学生交卷、客观题批改、教师查看成绩或学生查看已发布成绩。
9. 所有删除类操作必须二次确认。已产生提交记录的教学数据优先停用或归档，不做物理删除。
10. MVP 不支持学生重复提交；教师可在截止前撤销某学生的异常提交，使其重新作答，操作需记录审计日志。

## 1. 项目目标

### 1.1 产品目标

建设一个连接管理员、教师和学生的智能教学平台，完成以下最小业务闭环：

> 教师创建班级和题目 → 发布作业 → 学生在线答题 → 系统自动批改客观题、教师评阅简答题 → 生成成绩与知识点统计 → AI 提供学情分析和教学建议 → 系统推荐个性化练习 → 练习结果继续更新学情

### 1.2 MVP 要解决的问题

- 教师缺少统一的班级、题库、作业和成绩管理工具。
- 学生完成作业后不能及时获得客观题反馈、错题归纳和针对性练习。
- 教师需要手工汇总成绩和薄弱知识点，难以及时调整教学安排。
- AI 能力容易与核心业务耦合，需要建立可校验、可降级、可审计的服务边界。
- 管理员缺少对用户、班级、公共题库、AI 配置和平台运行数据的统一治理入口。

### 1.3 MVP 成功标准

在验收环境中满足以下条件，即认为 MVP 达成产品目标：

1. 三类角色均能登录，并且无法访问角色外页面或他人资源。
2. 一名教师可独立完成“创建班级—创建题目—发布作业—查看提交—完成评分—查看统计”的流程。
3. 一名学生可独立完成“加入班级—查看作业—在线答题—交卷—查看成绩解析—查看错题—完成推荐练习”的流程。
4. 客观题交卷后 5 秒内完成规则批改；含简答题的作业明确显示“待教师批改”，不提前发布最终总分。
5. 教师可查看作业平均分、提交率、题目正确率和知识点掌握度，统计结果可由原始答题记录复算。
6. AI 正常时可生成结构化学情、教学建议和题目答疑；AI 关闭或异常时核心闭环仍可完成。
7. 管理员可完成用户治理、班级查看与关闭、公共题库维护、AI 配置和平台指标查看。

### 1.4 本阶段不以其为成功标准的指标

MVP 不承诺学习成绩长期提升比例、AI 回答绝对正确率、自动生成题目质量或大规模并发能力；这些需要真实运营数据后另行制定指标。

### 3.5 自动批改、统计与 AI

| 功能 ID | 功能              | MVP 需求与边界                                                                                  | 验收入口 |
| ------- | ----------------- | ----------------------------------------------------------------------------------------------- | -------- |
| F-X01   | 客观题批改        | 单选/判断精确匹配；多选集合完全一致才得满分；填空按标准化后的可接受答案精确匹配，不做语义评分。 | AC-X01   |
| F-X02   | 成绩计算          | 总分为逐题得分之和；百分制展示值为 `总得分 / 作业总分 × 100`，保留 1 位小数。                   | AC-X02   |

## 4. MVP 范围

### 4.1 必须实现（In Scope）

- 学生自助注册、账号密码登录、退出、修改密码、三角色 RBAC、资源归属校验。
- 管理员创建和治理教师、管理员账号；公开注册不能指定角色。
- 教师班级创建、编辑、关闭、加班码和成员管理。
- 学生通过加班码加入班级。
- 教师私有题库、管理员公共题库及五种题型。
- 作业草稿、发布、截止控制、题目快照和提交状态。
- 学生草稿保存、单次提交和重复提交保护。
- 单选、多选、判断、填空题规则批改；简答题教师人工批改。
- 成绩发布、学生查看成绩解析、教师查看班级统计。
- 错题本、个人/班级知识点掌握度。
- 基于规则的个性化题目推荐和推荐练习记录。
- AI 学情分析、教师建议、学生题目答疑及规则降级。
- AI 服务配置、连接测试、限额和基础调用统计。
- 关键管理操作审计，以及所有核心页面的加载、空和错误状态。

### 4.2 明确限制

| 范围项     | MVP 限制                                                  |
| ---------- | --------------------------------------------------------- |
| 注册       | 仅学生可公开注册；教师和管理员账号由管理员创建。          |
| 班级归属   | 一个班级只有一名负责教师，不支持助教或多教师协作。        |
| 加入班级   | 学生通过加班码直接加入，不设教师审批流。                  |
| 作业提交   | 每名学生每份作业一次有效提交；异常情况由教师撤回后重做。  |
| 填空批改   | 仅按配置的可接受答案进行大小写/首尾空格标准化后精确匹配。 |
| 多选计分   | 全部选对且无多选才得分，不设部分分。                      |
| 简答题     | 教师人工评分；AI 仅提供建议且不可自动发布成绩。           |
| 成绩可见性 | 客观题作业提交后自动发布；含简答题作业由教师统一发布。    |
| 学情计算   | 只使用已发布成绩；数据不足时显示“暂无足够数据”。          |
| 推荐题     | 优先从现有题库检索，不由 AI 自由生成题目。                |
| AI 对话    | 围绕单道题的一问一答，不保存为无限上下文聊天。            |
| 管理员     | 可治理但不代替教师开展教学，不修改学生答案或成绩。        |

8. 规则推荐。
9. AI 分析、建议和答疑。

## 8. 核心业务流程

### 8.1 账号与权限流程

1. 管理员创建用户并分配角色。
2. 用户使用邮箱和密码登录。
3. 服务端验证账号、密码和启用状态，创建会话。
4. 用户进入对应角色工作台。
5. 每次访问资源时服务端重新校验角色与资源归属。
6. 用户停用、退出或修改密码后，相关会话失效。

异常边界：凭据错误不说明邮箱是否存在；停用账号拒绝登录；角色路由越权返回 403；资源 ID 越权返回 403/404。

### 8.2 教师建班与学生加入

1. 教师创建班级，系统生成唯一加班码。
2. 学生输入加班码。
3. 服务端校验班级存在、状态开放、码有效且学生未加入。
4. 系统建立班级成员关系，学生可看到该班已发布作业。
5. 教师可刷新加班码或移除学生，操作立即生效。

异常边界：无效码、已失效码、关闭班级和重复加入均不创建新成员记录；移除学生不删除历史成绩。

### 8.3 教师创建题目与发布作业

1. 教师创建符合题型规则的私有题目，或只读选择公共题目。
2. 教师创建作业草稿，选择自己的开放班级。
3. 教师添加题目并设置分值、说明和截止时间。
4. 发布前服务端完成输入、角色、归属、题目状态和时间校验。
5. 发布时保存题目、答案、解析、知识点和分值快照。
6. 作业对班级当前成员可见，发布后题库变更不影响该作业。

异常边界：空作业、总分为 0、截止时间已过、题目停用、班级不属于教师或班级关闭时均禁止发布。

### 8.4 学生答题、交卷与批改

1. 学生打开所属班级的有效作业，系统创建或恢复唯一草稿。
2. 学生逐题作答，系统保存草稿并显示保存结果。
3. 学生点击提交并二次确认。
4. 服务端校验成员关系、作业状态、截止时间和是否已提交。
5. 系统在事务中冻结答案快照并创建有效提交。
6. 规则引擎批改单选、多选、判断和填空题。
7. 纯客观题作业自动生成并发布成绩；含简答题的作业进入“待批改”。
8. 教师完成人工评分后发布最终成绩。

异常边界：重复或并发提交只成功一次；截止后的草稿不能提交；AI 故障不影响交卷和客观题批改。

### 8.5 成绩、错题与学情更新

1. 成绩发布后，系统计算总分和百分制分数。
2. 未满分题目以作业快照进入学生错题本。
3. 系统按已发布成绩重新聚合个人和班级知识点掌握度。
4. 教师查看作业/班级统计，学生查看个人成绩、错题和学情。
5. AI 服务基于匿名化统计生成补充分析；失败时展示规则摘要。

异常边界：未发布成绩不进入错题和学情；分母为 0 时不展示百分比；撤回成绩后统计应剔除对应结果。

### 8.6 个性化推荐闭环

1. 系统读取学生已发布成绩和知识点掌握度。
2. 选择最低掌握度知识点，并根据近期正确率确定难度区间。
3. 从学生有权访问、未停用且近期未做过的客观题中筛选候选。
4. 按知识点匹配、难度匹配和新鲜度排序，展示推荐理由。
5. 学生完成推荐练习，系统即时批改并记录结果。
6. 练习结果进入个人学情计算，下一轮推荐随之更新。

异常边界：没有学情数据时推荐基础公共题；无匹配题时显示空状态，不由 AI 临时编题；学生不能通过推荐接口读取标准答案。

### 8.7 AI 教学建议与题目答疑

1. 业务服务准备最小必要上下文并移除直接身份信息。
2. 统一 AI Service Layer 根据管理员配置调用供应商。
3. AI 返回 JSON，系统使用 Zod 校验。
4. 校验或请求失败后自动重试一次。
5. 第二次仍失败时，教学建议使用规则统计模板；题目答疑使用题目解析和通用解题引导。
6. 系统记录模型、耗时、成功状态、错误类别和令牌用量，不记录密钥和完整敏感输入。

异常边界：达到限额、配置缺失、超时和格式错误均触发降级；AI 回答不得修改答案、成绩和知识点统计。

### 9.6 发布验收门槛

发布 MVP 前必须同时满足：

1. `AC-C01` 至 `AC-X06` 全部通过，无阻断级或严重级缺陷。
2. 未登录、权限不足、参数错误、数据不存在、重复提交和 AI 异常测试全部通过。
3. 核心业务闭环端到端测试至少覆盖一份纯客观题作业和一份含简答题作业。
4. 自动化测试覆盖核心权限、批改算法、成绩计算、知识点统计、重复提交和 AI 降级。
5. 不存在跨教师、跨学生数据泄漏；不存在标准答案提前泄漏。
6. 数据库 migration 可在空库执行，seed 可创建三类验收账号；升级方案不删除已有核心数据。
7. `lint`、类型检查、测试和生产构建通过。
8. AI 完全关闭时，除 AI 建议和答疑质量下降外，其余核心功能可正常完成。

## 附录 A：统一状态建议

### 班级状态

- `ACTIVE`：可加入、可发布作业。
- `CLOSED`：不可加入、不可发布新作业，历史数据只读保留。

### 题目状态

- `ACTIVE`：可加入新作业或推荐。
- `INACTIVE`：不可新引用，历史快照继续有效。

### 作业状态

- `DRAFT`：仅教师可见和编辑。
- `PUBLISHED`：学生可见并可在截止前答题。
- `CLOSED`：教师提前关闭或到截止时间，不再接受提交。

### 提交与成绩状态

- `IN_PROGRESS`：学生存在草稿，尚未交卷。
- `SUBMITTED`：已交卷，规则批改处理中或等待状态判定。
- `PENDING_REVIEW`：含未完成人工批改的简答题。
- `GRADED`：已完成全部批改但成绩尚未发布。
- `PUBLISHED`：成绩和解析已对学生可见。
- `WITHDRAWN`：教师因异常撤回，不计入当前统计，允许重新作答。

## 附录 B：统一接口响应

成功：

```json
{
  "success": true,
  "data": {}
}
```

失败：

```json
{
  "success": false,
  "error": "可安全展示给用户的错误信息"
}
```

接口不得直接返回数据库错误、调用堆栈、密码散列、AI 密钥或第三方供应商的敏感原始响应。
