# V1.0 迭代一验收与使用指南

> 历史说明：本文记录 2026-07-30 验收时的“一次性初始账号”流程。自 2026-07-31 起，新名单导入改为创建待认领学生身份和班级预分配关系，学生在 `/register` 使用唯一学号与名单姓名自行认领；既有正式账号和首次改密流程继续兼容。

> 范围：课程模型与导入基础
>
> 验收日期：2026-07-30
>
> 计划书基线：《项目计划书》2.1 版

## 1. 验收范围

本迭代只验收以下能力：

- Python 程序设计课程模板、教师课程和班级关联。
- XLS、XLSX、UTF-8 CSV 学生名单上传、版本保留、字段映射和预览。
- 学生账号匹配或创建、自动入班、事务回滚和幂等执行。
- 一次性初始账号表、首次登录改密、权限隔离和审计。
- 原 MVP 核心闭环回归。

本迭代没有实现教学大纲解析、知识图谱、成绩导入与达成度、签到、Python 在线判题、V1.0 学情画像增强、自主练习增强、结课问卷或教学质量报告。

## 3. 课程模板和课程使用方式

执行安全的本地 seed 后，系统创建并保持以下内置模板可用：

- 模板编码：`python-programming-v1`
- 模板名称：`Python 程序设计`
- 版本：`1.0`
- 状态：内置、启用

管理员可在“课程模板”页面查看、创建、编辑、停用或重新启用模板。教师进入“课程管理”，选择启用模板，填写课程号、学期、名称和说明后创建课程。同一教师的“课程号 + 学期”不能重复。

课程创建后，教师只能关联自己名下且处于可用状态的班级。其他教师的课程和班级按资源不存在处理，避免暴露资源信息。

## 4. 名单模板要求

迭代一支持：

- 旧版 `.xls`。
- `.xlsx`。
- UTF-8 编码的 `.csv`。

计划书固定验收模板包含 1 个工作表和以下 10 列：

1. 学年学期(文本)
2. 课程号(文本)
3. 学号(文本)
4. 姓名(文本)
5. 班级(文本)
6. 成绩标识(文本)
7. 期末成绩(100.0%)(文本)
8. 特殊原因(文本)
9. 等级成绩类型(文本)
10. 备注(文本)

其中学年学期、课程号、学号、姓名和班级是本迭代必填字段。学号必须按文本保存；数值单元格、科学计数法、缺失值和文件内重复学号会产生阻断错误。系统支持教师确认自动映射，或在源表头存在差异时手动映射字段。

## 5. 导入流程

1. 进入教师端“课程管理”，打开目标课程。
2. 先把自己的班级关联到课程。
3. 进入“学生名单管理”，上传 XLS、XLSX 或 UTF-8 CSV。
4. 选择文件版本、目标班级、工作表和表头行。
5. 检查自动字段映射；必要时手动调整。
6. 查看新增账号、已注册账号、已在班级、课程不匹配、重复和非法行的逐行预览。
7. 阻断错误为零后确认映射并执行正式导入。
8. 如本批次创建了新账号，立即下载一次性账号表。

上传相同内容仍会产生新的文件版本，历史版本可继续下载。正式执行只允许使用当前最新文件版本对应的已确认预览，避免教师在上传新版本后误执行旧预览。

## 6. 匹配、事务和幂等规则

- 以规范化后的学号为主要身份匹配依据。
- 已存在学生账号不会被重置密码，也不会用名单姓名覆盖原资料。
- 已存在但未入班的学生只新增或恢复班级成员关系。
- 已在班级中的学生标记为“已入班”，不重复创建成员关系。
- 同一批次重复执行返回既有结果，不重复写入，也不再次返回明文凭据。
- 同一名单以新文件版本再次导入时，已创建学生会被识别为已注册或已入班。
- 并发执行通过 Serializable 事务、批次原子认领、唯一约束和有限重试保证正式数据只有一份。
- 预览只写导入批次和逐行暂存记录；有阻断错误时不能执行。
- 正式执行任一行出现角色或唯一标识冲突时，整批 User、UserProfile 和 ClassMembership 写入回滚。

## 7. 初始账号下载和首次改密

- 新账号使用随机一次性密码，数据库只保存 bcrypt 哈希。
- 明文凭据只存在于首次成功执行的响应和当前浏览器页面内存中。
- 账号表只包含本批次实际新建的账号，不包含已注册或已入班学生。
- CSV 导出会中和电子表格公式前缀，避免姓名、班级等字段触发公式执行。
- 教师只能记录一次成功下载；重复下载请求返回冲突。
- 下载后页面清除明文。刷新、离页、响应丢失或账号表遗失后，平台不能恢复旧密码，只能走密码重置。
- 新学生登录后只能进入首次改密页面；改密成功会清除原有会话并建立新会话。
- 平台不通过邮件、短信、微信或其他外部渠道发送账号。

## 8. 权限边界

| 操作                 | 管理员                   | 教师                           | 学生 |
| -------------------- | ------------------------ | ------------------------------ | ---- |
| 管理课程模板         | 允许                     | 只读启用模板                   | 禁止 |
| 创建课程、关联班级   | 禁止使用教师接口         | 仅自己的课程和班级             | 禁止 |
| 上传、预览、执行名单 | 管理员仅保留受控执行入口 | 仅自己的课程、文件、批次和班级 | 禁止 |
| 下载原名单           | 平台治理下载并审计       | 仅自己的资源并审计             | 禁止 |
| 获取一次性明文凭据   | 不返回                   | 仅导入发起流程一次             | 禁止 |

所有入口均在服务端验证身份、角色、资源归属和状态。跨教师访问统一返回 404；未登录返回 401；角色不符返回 403。

## 9. 已知限制

- 默认单文件上限为 5 MB，默认最多 1000 条数据，可通过安全环境变量在受控范围内调整。
- CSV 只接受 UTF-8；不支持 GBK/ANSI 自动探测。
- 固定验收样表为单工作表；多工作表文件需要教师明确选择，隐藏工作表不能导入。
- 公式单元格和合并单元格会被阻断，不会计算公式结果。
- 本迭代只使用名单前 5 个身份和课程字段完成开户入班；后 5 个成绩相关字段只保留在导入暂存数据中，不导入成绩。
- 一次性账号表不在服务器长期保存，无法恢复旧明文密码。
- 批量导入目前由受控请求同步执行；后续大规模后台任务化不属于本迭代。

## 10. 手动演示步骤

默认本地 seed 账号：

| 角色   | 账号                  | 密码          |
| ------ | --------------------- | ------------- |
| 管理员 | `admin@example.com`   | `Admin123!`   |
| 教师   | `teacher@example.com` | `Teacher123!` |
| 学生   | `student@example.com` | `Student123!` |

仅可在本地演示环境使用这些默认密码。

1. 以管理员登录，打开“课程模板”，确认 `Python 程序设计` 模板处于启用状态。
2. 以教师登录，创建一个班级。
3. 打开“课程管理”，使用 Python 模板创建课程，并关联刚创建的班级。
4. 进入课程的“学生名单管理”，先上传含一条非法学号的测试 CSV，确认逐行错误并验证无法执行。
5. 上传去标识化的合法 XLS、XLSX 或 UTF-8 CSV，确认新文件显示为新版本，旧版本仍可下载。
6. 检查映射和预览分类，确认后执行导入。
7. 下载一次性账号表，确认只含新账号；再次下载应被拒绝。
8. 再次上传同一名单并执行，确认不新建账号、不重复入班。
9. 使用账号表中的新学号和初始密码登录，确认被强制进入首次改密页面。
10. 修改密码后进入学生端，再以教师验证该学生已在目标班级。
11. 最后按 `docs/MVP-ACCEPTANCE.md` 的教师、学生和管理员路径抽查原 MVP 作业闭环。

## 12. 数据库和回滚说明

本次验收修复没有新增 Schema 或 migration。迭代一已有 migration 提供课程、模板、文件版本、导入批次、导入行、首次账号下载状态和相关审计枚举。

- 原有用户、班级、作业、提交、成绩、分析、推荐和通知数据不做删除或语义变更。
- 名单正式执行使用事务；失败时整批正式数据回滚，失败状态和脱敏审计保留用于诊断。
- 文件新版本追加保存，历史版本不被覆盖；回退时可重新选择历史文件查看和下载，但正式执行需要基于当前版本重新预览。
