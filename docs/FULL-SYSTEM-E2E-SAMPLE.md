# 智学课堂 V1.0 全流程测试样例

> 适用版本：2026-08-18 当前工作区
> 目标：从课程初始化开始，逐步验证大纲、图谱、名单、成绩、作业、判题、画像、推荐、问卷和教学质量报告。
> 数据性质：全部为虚构数据，只能用于本地或隔离测试环境。

## 1. 样例文件

| 文件                                                  | 用途                               | 固定检查点                                         |
| ----------------------------------------------------- | ---------------------------------- | -------------------------------------------------- |
| `output/pdf/python-programming-2024-e2e-syllabus.pdf` | 文本型教学大纲上传与 AI 结构化解析 | 3 项目标、11 章、8 个实验、32/20/12 学时、5 项权重 |
| `outputs/full-system-e2e/student-roster-e2e.xlsx`     | 固定 10 列名单导入                 | 12 条待认领身份、学号前导零、重复导入幂等          |
| `outputs/full-system-e2e/course-grades-e2e.xlsx`      | 固定 10 列成绩导入                 | 5 个数值成绩、1 个“缺考”特殊状态                   |

PDF 已验证为 A4、7 页、未加密、可提取文本。两个 XLSX 都只有一个工作表、10 列；项目解析器复验后学号 `000202600001` 保持为文本，不丢前导零。

## 2. 测试前准备

1. 使用本地或隔离测试数据库，禁止连接生产库。
2. 应用全部 migration，并执行 `npm run prisma:seed`。
3. 启动 Web、后台 worker 和远程 Python 沙箱；真实判题必须先通过沙箱能力检查。
4. 真实 AI 使用 DeepSeek V4 时建议明确配置：

   ```dotenv
   AI_PROVIDER=openai-compatible
   AI_API_TYPE=chat-completions
   AI_BASE_URL=https://api.deepseek.com/v1
   AI_MODEL=deepseek-v4-flash
   AI_THINKING_MODE=disabled
   SYLLABUS_AI_TIMEOUT_MS=180000
   SYLLABUS_AI_MAX_COMPLETION_TOKENS=8192
   ```

   当前代码在 `AI_BASE_URL` 主机为 `api.deepseek.com` 且未设置 `AI_THINKING_MODE` 时，会自动关闭默认思考模式。结构化 JSON 不应消耗输出额度生成 `reasoning_content`。

5. 使用 seed 教师登录：`teacher@example.com` / `Teacher123!`。本地部署前应按环境覆盖默认密码。

### 3.3 题库与作业

创建以下四道课程级题目，并绑定当前正式图谱中的 Concept。编码以实际解析结果为准；名称匹配时优先选下列知识点。

| 题目                      | 类型          | 分值 | 难度 | 答案/批改        | Concept                    |
| ------------------------- | ------------- | ---: | ---: | ---------------- | -------------------------- |
| `if` 分支判断             | 单选题        |   10 |    1 | B                | 条件分支（主）             |
| `range(5)` 的最后一个整数 | 填空题        |   10 |    1 | `4`              | for循环（主）              |
| 列表与字典的差异          | 简答题        |   10 |    2 | 人工批改         | 列表（主）、字典（次）     |
| 正整数求和                | Python 编程题 |   20 |    2 | 隐藏用例自动判题 | 循环（主）、输入输出（次） |

单选题正文：

> 当需要根据条件选择不同执行路径时，最适合使用哪种结构？
> A. 只使用注释；B. `if/elif/else`；C. 只使用变量赋值；D. 只使用 `import`

简答题参考答案：

> 列表是有序可变序列，通常按位置访问；字典保存键值映射，通常按唯一键访问。两者都可动态增删元素，但数据组织和查找方式不同。

Python 编程题正文：

> 从标准输入读取若干整数，输出其中所有正整数之和。没有正整数时输出 `0`。

标准代码：

```python
import sys

numbers = map(int, sys.stdin.read().split())
print(sum(number for number in numbers if number > 0))
```

公开样例：输入 `1 -2 3 0`，输出 `4`。

隐藏用例只在教师端配置，不得出现在学生接口：

| 输入       | 期望输出 | 权重 |
| ---------- | -------- | ---: |
| `-1 -2 -3` | `0`      |  30% |
| `5`        | `5`      |  30% |
| `10 -3 2`  | `12`     |  40% |

创建作业 `E2E-01 Python基础与控制结构`，总分 50，允许学生在截止前提交。首次发布后记录题目-Concept 快照。

## 4. 逐步验收

### 步骤 1：课程、班级与关联

1. 教师创建第 3.1 节课程。
2. 创建 `Python验收1班` 并关联课程。
3. 刷新课程详情页。

预期：课程与班级都归属当前教师；另一教师不能访问该课程；未登录接口返回 401，跨教师资源不暴露是否存在。

### 步骤 2：上传并解析教学大纲

1. 上传 `python-programming-2024-e2e-syllabus.pdf`。
2. 点击“重新解析”。
3. 等待解析完成，逐页对照审核草稿。

必须核对：

- 课程目标 3 项。
- 理论章节 11 章，理论 20 学时。
- 实验项目 8 项，实践 12 学时。
- 总学时 32。
- 平时表现、课程作业、期中考试、课程实验、期末考试的权重依次为 10%、5%、5%、20%、60%。
- 字段来源引用的页码真实存在。

若 Provider 第一次返回空内容，系统应自动重试一次；若返回 `finish_reason=length`，页面应显示“输出因长度限制被截断”，不能再误报为原始 `PROVIDER_EMPTY_RESPONSE`。

### 步骤 3：审核和发布正式大纲

1. 修正任何 AI 表述偏差。
2. 保存审核修订。
3. 显式发布正式版本。

预期：发布的是不可变版本；再次编辑需创建新审核修订；重新上传新 PDF 不覆盖旧正式版本。

### 步骤 4：生成、审核和发布知识图谱

1. 基于当前正式大纲生成基础草稿。
2. 检查 11 个章节节点、对应知识点和 `CONTAINS` 关系。
3. 检查 AI 只新增少量 `RELATED` 建议，失败时基础草稿仍可用。
4. 搜索“条件分支”“列表”“文件读写”，打开节点详情并检查来源。
5. 保存审核稿并发布。

预期：`KnowledgeGraphConcept` 作为课程内稳定身份；正式发布版本可用于题目绑定、画像和推荐。

### 步骤 5：名单导入、幂等和认领

1. 上传 `student-roster-e2e.xlsx` 并预览。
2. 首次执行应新增 12 条待认领身份和班级预分配，不创建默认密码账号。
3. 使用同一文件再次预览和执行。
4. 在注册页依次认领第 3.2 节前六个账号。

预期：

- 学号保留 3 个前导零。
- 第二次导入为已存在/已预分配，不重复创建。
- 前六人认领后自动入班，后六人仍为待认领。
- 相同学号并发认领只能一个成功；失败事务不得残留用户、绑定或班级成员。

### 步骤 6：考核方案和成绩台账

1. 从正式大纲生成考核方案草稿。
2. 核对五项权重合计 100%，目标映射合理。
3. 保存审核并发布方案。
4. 为 `Python验收1班` 建立成绩台账。

预期：权重不等于 100% 时不能发布；已发布方案不可静默覆盖。

### 步骤 7：题目绑定与发布快照

1. 创建第 3.3 节四道题。
2. 绑定主/次 Concept，保存来源图谱版本。
3. 创建并发布作业。
4. 发布后修改其中一道题的 Concept 绑定。

预期：作业历史快照保持首次发布时的绑定，不随题目或新图谱版本变化。

### 步骤 8：公开运行、提交和隐藏判题

学生 01：

- 单选 B；填空 `4`；简答按参考答案作答。
- Python 公开运行使用正确代码，公开样例输出 `4`，随后提交。

学生 02：

- 单选 D；填空 `5`；简答只写“都是容器”。
- Python 代码故意写成 `print(sum(`，用于验证语法错误分类。

预期：公开运行不执行隐藏用例；正式提交后创建异步 Attempt；学生只能看到用例通过数、得分和安全错误类型，不能看到隐藏输入、标准代码、执行器地址或密钥。

### 步骤 9：人工批改、成绩发布和追加式证据

1. 教师给学生 01 简答题 9/10，反馈“结论准确，可补充访问复杂度”。
2. 给学生 02 简答题 3/10，反馈“需说明有序序列与键值映射差异”。
3. 发布作业成绩。
4. 将学生 02 简答题改为 5/10并填写修改原因，再执行一次撤销或重判验证。

预期：重新批改和撤销生成新修订，不覆盖旧证据；只有成功解析到发布快照 Concept 的已批改答案进入课程掌握度。

### 步骤 10：签到与画像

1. 创建一次当前时间窗内的签到。
2. 学生 01 正常签到；学生 02 不签到。
3. 结束后结算缺勤，再由教师将学生 02 纠正为“请假”，原因写“隔离验收修正”。
4. 生成学生画像快照并查看证据下钻。

预期：纠正保留原状态和原因；出勤、活跃度、自述、客观掌握度分开显示；证据不足的学生显示“证据不足”。

### 步骤 11：课程推荐、自主练习与自我反思

1. 将“条件分支、for循环、列表、字典”标记为已授范围。
2. 学生 02 请求 3 道、难度 1-2 的薄弱知识点练习。
3. 检查每道题的推荐理由、画像版本和规则版本。
4. 学生输入自述：“循环边界容易写错，希望做3道简单循环题。”
5. 确认结构化条件后完成练习，再修改或删除自述证据。

预期：推荐不超出课程、进度和已审核题库；自述不覆盖客观掌握度；完成后追加反馈、掌握度和画像修订。

### 步骤 12：导入固定成绩与目标达成度

1. 确认前六名学生均已认领并在班。
2. 上传 `course-grades-e2e.xlsx` 预览并执行。
3. 发布成绩，生成课程目标达成度。

预期：5 个数值成绩分别为 92、86、78、69、58；学生 06 为“缺考”，不能当作普通 0 分；输入中的备注不改变确定性计算；新成绩发布后旧达成度只标记过期。

### 步骤 13：结课问卷和小样本保护

1. 从正式大纲生成问卷草稿。
2. 选择 `Python验收1班`、匿名模式，明确“不计入成绩”。
3. 保留课程目标自评、教学质量五级量表和 3 道开放题后发布。
4. 先让学生 01-04 提交，查看统计；再让学生 05-06 提交。

建议开放题答案：

| 学生 | 最有帮助       | 仍感困难     | 改进建议         |
| ---- | -------------- | ------------ | ---------------- |
| 01   | 实验和即时反馈 | 文件异常处理 | 增加文件练习     |
| 02   | 循环可视化示例 | 循环边界     | 增加分层练习     |
| 03   | 小组调试       | 字典嵌套     | 增加数据处理案例 |
| 04   | 编程题公开样例 | 函数参数     | 增加参数对比例题 |
| 05   | 错题反馈       | 面向对象继承 | 放慢继承章节节奏 |
| 06   | 综合项目       | 模块化测试   | 增加测试模板     |

预期：4 份时只显示人数和响应率；达到 6 份后才显示量表细分和脱敏主题。匿名回答不得在教师接口、审计或下载中关联到单个学生。

### 步骤 14：教学质量报告

1. 关闭问卷并生成最新汇总修订。
2. 从课程详情进入教学质量报告，优先选择平台正式成绩；也可用成绩样例验证隔离上传源。
3. 启动后台生成，等待确定性统计和 AI 文字初稿。
4. 逐项审核课程目标分析、学生评价、课程总结和改进措施。
5. 确认后生成正式 DOCX 和成绩工作簿并下载。

预期：

- 数字与图表来自冻结快照，AI 只写去标识化分析文字。
- AI 失败时仍能生成确定性基础报告。
- 课程评价小组、学院意见、签字和日期保持空白。
- DOCX 可重新打开，表格、图表和关键字段存在；下载要求教师与课程归属校验并禁止公共缓存。

### 步骤 15：通知、权限和回归

检查作业发布、批改完成、问卷发布和推荐更新通知；再执行以下负面测试：

- 学生访问教师 API：403。
- 教师 2 访问教师 1 课程资源：404 或等价防枚举响应。
- 学生 01 访问学生 02 成绩、画像或提交：拒绝。
- 匿名问卷教师端请求单份答卷身份：不提供。
- Python 学生接口请求隐藏用例字段：不提供。
- AI Provider 断开后登录、交卷、确定性成绩和已发布成绩查看仍可用。

## 5. 完成判定

完整样例通过需同时满足：

- 三种角色和跨资源授权无越权。
- 大纲、图谱、方案、作业绑定、证据、掌握度、画像、推荐、问卷汇总和报告都保留版本/修订来源。
- 学号前导零、重复导入、待认领和特殊成绩状态正确。
- Python 公开运行与隐藏判题隔离，错误类型和确定性得分可复现。
- 匿名与小样本保护有效。
- 最终 DOCX/XLSX 可下载、重新打开并与平台统计一致。

该手册是人工登录态全流程样例，不替代自动单测、HTTP 集成、空库 migration、生产构建和真实沙箱专项验收。
