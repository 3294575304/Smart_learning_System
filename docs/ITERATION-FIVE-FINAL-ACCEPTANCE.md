## 1. 验收结论

迭代五 A–E 已形成可复现的完整技术链路：

> 正式课程图谱 → 教师审核题目主/次 Concept 绑定 → 作业发布冻结题目与判题配置 → 学生公开运行或正式提交 → 独立 worker 调用隔离执行器 → 隐藏用例确定性评分 → 追加式学习事件与 Concept 证据 → 版本化课程掌握度与画像快照 → 师生按课程归属查看结果和依据

本次收尾确认：

- 远程 gVisor 执行器的禁网、CPU、墙钟、内存、宿主文件、进程、输出和宿主秘密 8 项安全能力已有 2026-08-10 脱敏实测证据。
- Next.js 生产服务、独立判题 worker 和远程 gVisor 的真实纵向集成已有公开运行、隐藏判题、确定性成绩、隐藏字段隔离、学习事件和课程 Concept 证据。
- 2026-08-11 在当前提交候选上重新通过空库 migration、seed、HTTP/数据库集成、全量单测、格式、Lint、类型、Prisma 和三套生产构建。
- 浏览器人工核验覆盖教师编程题配置、公开/隐藏用例、课程图谱绑定、已发布编程作业成绩与知识点统计、画像证据状态，以及非课程成员访问返回统一 404。
- 当前开发数据中的演示题没有正式课程 Concept 绑定，因此画像正确显示“无证据”，未把 MVP 全局知识点统计误投影为课程画像；正式 Concept 证据由独立纵向集成用例验证。

迭代五专项验收通过不代表 V1.0 整体完成。课程图谱驱动推荐、自主练习、AI 自我反思、结课问卷、DOCX 质量报告和最终界面整合仍待开发。

## 2. 已实现功能

### 2.1 题目映射与历史快照

- 教师维护课程级主/次 Concept 绑定，保存来源图谱版本、版本节点和乐观并发修订。
- 作业首次发布冻结题目绑定、图谱解析状态、Python 配置修订、测试用例哈希和执行规则版本。
- 后续修改题目绑定、判题配置或发布新图谱均不改写历史作业。
- AI 批量匹配只生成候选；严格校验输入 ID 范围，失败安全降级，教师确认前不进入正式计算，也不覆盖人工绑定。

### 2.2 任务、隔离执行与 Python 判题

- 通用后台任务支持幂等键、租约、心跳、重试、恢复、取消、进度和安全错误分类。
- 独立判题 worker 调用远程执行器；Next.js 请求进程不直接执行学生代码。
- 教师配置标准代码、初始代码、公开样例、隐藏用例、分值和 CPU/内存/时间/进程/输出限制。
- 学生公开运行不计分；正式提交异步执行隐藏用例并确定性评分。
- 学生 DTO 不返回隐藏输入、期望输出、正式用例 stdout/stderr、执行器路径或内部异常。
- 语法错误、运行错误、超时、内存超限和系统错误分离；系统错误保持可重试，不按学生零分处理。
- 重判与撤销追加新 Attempt 和事件修订，不覆盖历史；后台任务重试不会重复投影成绩、事件或证据。
- 执行请求 ID 同一任务内稳定、不同后台任务隔离，避免恢复任务误复用旧执行结果。

### 2.3 学习事件、掌握度与画像

- 既有客观/人工评分与 Python 正式判题统一写入版本化学习事件契约。
- 只有发布快照成功解析到正式图谱的有效评分才形成 `StudentAnswerConceptEvidence`。
- 课程掌握度按有效得分/可得分确定性计算，保存输入指纹、规则版本和不可变修订。
- 画像保存图谱版本、掌握度修订、事件水位、输入指纹和规则版本。
- 出勤、活跃度、自我反思和客观掌握度分维度保存；没有采集源时明确显示“无证据”。
- 师生页面支持结论、更新时间、置信度、证据不足和证据下钻；跨课程、跨教师和非本人访问在服务端隔离。

### 2.4 本地部署加固

- Windows 本地生产构建使用 `.data/next-production`，不与开发服务器 `.next` 共用 manifest。
- 安装脚本校验生产 routes manifest，并为 Next.js、SSH 隧道和判题 worker 配置失败重启及“恢复用户活动时不停机”。
- 轮询中断时前端显示“状态查询中断，请重试查询”，不继续展示可能过期的运行百分比。
- 当前机器未安装 `Zhixue-*` 计划任务；无人登录开机自启属于部署选择，需使用专用服务账户或 `SYSTEM` 后重新核对密钥和数据库目录 ACL。

## 4. 数据库、配置与回滚

- 本次验收收尾没有修改 Prisma Schema、migration 或 seed。
- Windows 独立生产构建目录和计划任务设置是部署脚本变化，不改变数据库语义。
- 如回退部署脚本，可停止使用 `.data/next-production` 并恢复旧任务配置；历史 Attempt、事件、证据、掌握度和画像不得物理删除或覆盖。
- 仍不自动回填能力上线前已发布作业。未来如需回填，必须另行设计范围预览、审计、幂等和回滚方案。

## 5. 下一步开发建议

下一阶段进入迭代六“课程图谱驱动推荐”，建议按以下顺序推进：

1. 定义从 `LearnerProfileSnapshot`、`StudentCourseConceptMasteryRevision` 和正式图谱读取的兼容层，不复制第二套课程掌握度。
2. 实现课程范围、教学进度、题目审核/启用、答案解析、难度差、近期重复和先修关系硬过滤。
3. 保存推荐目标 Concept、画像版本、图谱版本、规则版本、排序分、理由和完成后的掌握度变化。
4. 复用现有练习作答和错题闭环，先支持学生结构化选择知识点、题型、题量和难度。
5. 最后接入 AI 对话，把自然语言目标转换为可确认的结构化条件；AI 失败时保留确定性推荐。
6. 迭代六稳定后再开发结课问卷，随后以正式成绩、达成度、出勤和问卷快照生成 DOCX 报告。

部署侧可并行但不阻塞业务迭代：如目标机器要求无人登录持续运行，再将 Next.js、SSH 隧道和 worker 改为服务账户或 Windows/Linux 服务，并复跑真实安全与纵向集成证据。
